# T26 交付结果层的两件套与卡片读数

- 状态：本地实现与验收完成（GitHub #28 未在本阶段更新）
- 类型：vertical
- 原计划阶段：README TODO · 成功与失败界面变更
- 父级规格：[结果层 spec](result-layer.md)（GitHub [#26](https://github.com/CaiYan12/2048/issues/26)）
- SPEC 用户故事：1–10、14、18、20
- Blocked by: T25

## 交付范围

把不透明满盖的结果层改成「**半透明遮罩 + 不透明卡片**」两件套：三种非对局阶段共用同一结构，
遮罩按阶段分三档；卡片补上分数、最高分、步数、新纪录四项读数；最高分按「结算那一刻的风格」
归属。三套风格只出 token 与 CSS，**不新增第四个插槽**。三处 `styles.css` 注释与三张设计卡 §6
就地改写并指向 ADR-0008。

## 验收标准

- [x] 三种阶段渲染同一结构：遮罩盖住棋盘、卡片坐在遮罩上。`.overlay` 仍是棋盘那个
      `position: absolute; inset: 0` 的兄弟节点，矩形与棋盘逐像素相同、`z-index: 3` 不变。
- [x] 棋盘留在文档里，格子一枚不少、终局数值不变；`elementFromPoint` 打棋盘内四个点仍落在
      `[data-panel]` 内。**现有两条几何断言不改断言**，只改写解释「不透明满盖」的那段注释。
- [x] 遮罩计算背景在三个阶段都半透明，强度按 `stuck`（最亮）→ `won` → `ended`（最暗）排列。
      三档由各风格自己的 token 提供；方向（压暗 / 起雾）由 `/design-flow` 逐套定，并在该套
      设计卡里**用文字回答**「这一套的遮罩是否让棋盘退后」。
- [x] 卡片背景不透明；卡片文字与按钮的对比度**不低于今天**——没有任何一处对比度声明为迁就
      遮罩而放松。
- [x] 卡片显示分数、最高分、步数、新纪录标记；标题、那一句话、四个按钮一字不改。
- [x] 步数读有效 Move 计数：撤销一步它减一，作弊交换不动它；标签写「步数」。
- [x] store 记住结算那一刻的风格：`ended` 读那条记录，`won` / `stuck` 读当前风格的记录。
      该字段**不持久化**——结算即清档，刷新后看不到结果层，所以它没有需要跨刷新存活的东西。
- [x] 新纪录是一个**纯判定**：拿本局分数与结算前那条记录比。取值点在写入处，不做事后重建
      （结算写入是幂等的，写完不留「之前是多少」）。
- [x] 作弊交换挑选期间结果层整块隐藏（既有分支不删，遮罩照旧斥指针），挑选完成或取消后回来。
- [x] 三张设计卡 §6 与三处 `styles.css` 注释改写为「半透明遮罩 + 不透明卡片」并指向 ADR-0008；
      全仓不再有任何一处说「用不透明底色而不是半透明」。

## 已接受的处理（不当作缺陷，但记下来）

- **「撤销让步数减一」在浏览器里证不了**：撤销会把 `phase` 一并搬回 `playing`，结果层当场不在
  画面上，三个阶段皆然。所以浏览器契约只断「四项读数数值正确」，减一那条由单测用真实 store
  路径钉住，spec 注释里写明了这个边界面。
- **两轮全量里 `tile-motion.spec.ts` 各超时一次**（30s 等不到「开始游戏」，5 个 spec 文件
  4 worker 抢一个 preview 服务）。单独重跑 4/4 过，两轮全量均 0 failed——判为负载抖动。
- **AGENTS.md 写的「763 unit tests / 39 files」与当前树对不上**；判断回归一律用 `git stash`
  取的实测基线（本次为 741 / 40），不拿文档里的旧数字当准。
