# 风格是一个文件夹，棋盘渲染固定结构 + 装饰插槽 + 呈现插槽

每套风格是 `themes/<id>/` 下的 `tokens.css` + `styles.css` + `config.ts` + `toast.tsx`；棋盘
组件只渲染一套固定 DOM 结构，另留两个装饰插槽（`boardOverlay` / `tileOverlay`）交给风格填，
外壳层另有一个呈现插槽（`toast`）。

**为什么**：本次先用 Classic、Material、Claude 验证扩展边界；长期规划中的 Frutiger Aero
玻璃 gloss、Terminal CRT 扫描线、Web 2000 斜面边框差的是**结构**，不只是颜色——单纯换
CSS 变量做不出这些效果。
但让每套风格替换整块 React 组件树，又会让十来份平行实现各自腐烂、bug 修十来遍。固定
结构 + 插槽是这两者之间唯一站得住的位置。

**Considered Options**

- 只换 CSS 变量：远期特色风格会被砍残，Aero 的 gloss 和 Terminal 的扫描线直接
  做不出来。
- 风格自带组件：平行实现，作弊交换、撤销历史、键盘与 `aria-live` 全要重接十来遍，
  加新风格的门槛会高到没人加。

**两类插槽（2026-09-28 增补，同日实现落地）**

从这一天起插槽不止一种，所以把两类分开命名，免得「插槽」一词同时指两件不同的事：

- **装饰插槽**（`boardOverlay` / `tileOverlay`）：**只许装饰**。棋盘 DOM 的结构、交互与方块
  身份都归固定组件所有，插槽只能往既定位置上加皮。
- **呈现插槽**（`toast`）：**拥有结构与行为**。它渲染在棋盘之外，因为它要呈现的消息与棋盘
  无关；风格自己决定长相与消失表现（约 5 秒自动消失、悬停或聚焦时暂停、`role="status"`
  播报、最多三条堆叠），宿主只负责「什么时候该有一条」。

**为什么接受它与原则相冲**：呈现插槽让三套风格各写一份 toast 的结构与消失逻辑，这与「固定
结构」反着来。接受它的理由是祝贺提示恰恰是各风格最该有自己长相的地方，而它的行为面窄到
一套共享测试能对三套风格逐套钉住——宽度换深度，这里换得值。

**Consequences**

加一套风格 = 加一个文件夹，引擎零改动。但风格**不能**把棋盘变成 ASCII 字符画这类结构性
改写——这是这套机制明确划出的边界，不是缺陷。
