# 规则内核与渲染层分离，核心签入可注入 RNG

游戏规则全部住在不碰 DOM 的纯函数层，棋盘渲染与交互是另一层；核心函数的随机源由调用方
注入，默认才是 `Math.random`。

**为什么**：Daily 模式要求同一个日期推出同一局，纯逻辑测试也要求「给定种子就能断言
第 7 步出现什么」——两者都要求随机源可替换。核心直接调 `Math.random` 的话这两件事都
做不了，而事后补要改每一个调用点。

**Considered Options**

- 纯 `Math.random`，Daily 内部单独哈希：测试仍然钉不死依赖随机的行为，合并链和生成
  位置都测不了。
- 全局可替换单例：隐式状态，测试之间会互相污染，比显式传参更难查。

**Consequences**

核心签名多一个 `rng` 参数；纯逻辑层的每个测试都是确定性的，CI 里跑出可复现结果。
字符串日期到种子的哈希算法写在核心旁边，可单独测。
