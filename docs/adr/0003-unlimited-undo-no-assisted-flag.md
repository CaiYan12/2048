# 撤销次数无限，且不加 assisted 标记

撤销不做任何次数限制，也不标记「本局用过撤销」；使用过撤销的一局照样计入最高分与统计。

**为什么**：这是练手 + 娱乐项目，平衡性不在目标内，记录本来就是给自己看的玩具。曾经考虑过
「有限撤销」和「用过撤销就不计分」，但那两个都是在为一个我们不想要的产品形态（竞技完整性）
服务，属于过度设计。

**Considered Options**

- 3 步有限撤销：能救手滑，但「绝不丢进度」这个真实诉求没被满足。
- 无限撤销 + `assisted` 标记：一个布尔字段，但随之要改写入处、UI 要提示、Daily 的语义
  也变复杂——为一个不存在的需求加三处代码。

**Consequences**

撤销历史不能截断到最近 N 步，否则无法兑现“逐步回到开局”。初版为每次有效移动或交换保留
完整前态，长局内存与持久化成本必须测量；以后若要压缩，可用可还原的事件记录或检查点，但
不得只留计数器并丢失旧状态。浏览器存储失败时须明确提示，不能把未保存的历史称为可恢复。
最高分与统计的数字**不要当真**——本项目刻意不做任何假装权威的东西（比如全球排行榜），
统计的用途是看自己的覆盖面，不是比高低。
