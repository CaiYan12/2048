## 1. 障碍与生成

### Walls 障碍坐标

零基坐标，2×2 居中障碍块：

```
          col 0   1   2   3
row 0      .     W   W    .
row 1      .     W   W    .
row 2      .     .    .    .
row 3      .     .    .    .
```

四个坐标：`(1,1)`、`(1,2)`、`(2,1)`、`(2,2)`（零基，`[row][col]`）。

其余 **12 个格子**为可玩格。

### 开局生成

Walls 模式开局在 **12 个可玩格**中生成两个方块，**不得占用同一格**。
生成两次，每次从未被占用的可玩格中独立随机选取。

### 生成权重

模式差异来自**棋盘与合并规则**，不来自生成规则——这样生成最容易被验证。

| 模式 | 生成值 | 权重 |
| --- | --- | --- |
| Classic | 2 / 4 | 90% / 10% |
| Big Board | 2 / 4 | 90% / 10% |
| Walls | 2 / 4 | 90% / 10% |
| Daily | 2 / 4 | 90% / 10% |
| Time Attack | 2 / 4 | 90% / 10% |
| Fibonacci | 1 / 2 | **90% / 10%** |

即：**所有模式的低值项都是 90%，高值项都是 10%**，唯一区别是这两个值本身是什么。

## 2. Fibonacci 合并顺序

规则：**先沿移动方向压紧，再从「移动目标边」向另一端逐对扫描；满足合并表即合并；
合并产物在本次移动中不能再次合并。**

「移动目标边」= 方块被推向的那一边。向左则从左边缘扫，向右则从右边缘扫，
向上从上行扫，向下从下行扫。

分数增加 **合并产物的数值**。

### 例子（4 格行，左/右各一）

| 输入（压紧后） | 方向 | 结果 | 分数增量 | 过程 |
| --- | --- | --- | --- | --- |
| `[1, 2, 3]` | 左 | `[3, 3]` | +3 | 从左扫：`1+2=3`（产物），剩 `3` 落入 → `[3, 3]` |
| `[1, 2, 3]` | 右 | `[1, 5]` | +5 | 从右扫：`2+3=5`（产物），剩 `1` → `[1, 5]` |

两个例子的扫描起点不同，因此合并对也不同——这正是「从目标边扫」的可观察后果。

### 补充例子（用于钉死「产物不再合并」）

| 输入 | 方向 | 结果 | 说明 |
| --- | --- | --- | --- |
| `[1, 1, 2]` | 左 | `[2, 2]` | `1+1=2` 是产物，不能再与后面的 `2` 合并 |
| `[1, 1, 1, 1]` | 左 | `[2, 2]` | 两对独立合并，各自产物不再参与 |
| `[2, 3, 5]` | 左 | `[5, 5]` | `2+3=5` 产物，`5` 落入 |
| `[2, 3, 5]` | 右 | `[2, 8]` | `3+5=8` 产物，`2` 落入 |

### 合并表（斐波那契）

```
1 + 1 → 2
1 + 2 → 3
2 + 3 → 5
3 + 5 → 8
5 + 8 → 13
…按斐波那契数列延续
```

目标块 **2584**（斐波那契数）。

## 3. 终局、恢复与结算

**达标只是胜利里程碑，不是终局。** 达成目标块 → 胜利面板，玩家可选「继续玩」或结算。

**死局先给可恢复面板**，不直接判负：允许 Undo 或作弊交换；
只有点击「结束并记录」，或从该面板点「新游戏」时，才真正结算。

**活跃局中直接「新游戏」= 放弃本局**，不写任何记录。

**Time Attack 到时立即结算**，此后不能 Undo、不能交换。

**结算只执行一次**，成绩归**结算那一刻所处的风格**。

### 状态图

```
                    ┌──────────────┐
      开局          │              │
   ───────────────► │   playing    │ ◄─────────┐
                    │  （活跃局）   │           │
                    └───┬───┬───┬───┘           │
            合出目标块   │   │   │ 无合法移动      │ 恢复成功
                        ▼   │   ▼               │ (Undo / 交换)
                    ┌──────────────┐       ┌──────────────┐
                    │     won      │       │    stuck     │
                    │ （胜利里程碑）│       │ （可恢复面板）│
                    └──┬────┬──────┘       └───┬──────┬───┘
             「继续玩」 │    │「结束并记录」       │      │
                       │    └──────────────┐    │      │
                       │                   │    │      │
                       │    ┌──────────────┘    │      │
                       │    ▼                   │      │
                       │  ┌──────────────────┐  │      │
                       │  │ ended（已结算）  │◄─┼──────┤
                       │  │ · 结算只一次     │  │      │
                       │  │ · 记录归结算风格  │  │      │
                       │  │ · 此后不可 Undo  │  │      │
                       │  │   / 交换         │  │      │
                       │  └──────────────────┘  │      │
                       │        ▲              │      │
                       └────────┼──────────────┘      │
                                │  「结束并记录」      │
                                │                     ▼
                    ┌───────────────────────────┐  （从 stuck 结算）
                    │      won ──「新游戏」      │
                    └───────────────────────────┘
```

> **状态图补订（2026-09-26，实现 T04 时由执行控制人补上，非新裁决）**
>
> 原图漏画了 `won ──「结束并记录」──► ended` 这条边，而本节的正文第一句就写着
> 「达成目标块 → 胜利面板，玩家可选『继续玩』**或结算**」——正文有、图没有，自相矛盾。
> 本次只把图补齐到与正文一致，**没有新增或改变任何规则**。定稿时漏这条边的后果是实的：
> 少了它，胜局唯一能写进记录的途径就是**故意把自己走死**，SPEC §3.3 的
> 「Win-related records use the style at settlement, including a run that reached the target and
> continued」 也无从实现。T04 按正文实现这条边，`endReason` 取 `won`。
>
> 其余路径不变：

其他进入 ended 的路径：
  · playing ──「新游戏」──► ended（放弃本局，不写记录）
  · playing ──Time Attack 到时──► ended（立即结算，此后不可 Undo / 交换）
  · stuck   ──「新游戏」──► ended（同放弃本局）
  · won     ──「新游戏」──► ended（放弃本局，不写记录）
```

关键不变量：

1. `won` 不是终局——它只是一个里程碑状态，可无限次进出。
2. `stuck` 不是终局——它是给你 Undo 和作弊交换的。
3. **只有 `ended` 会写记录**，且只写一次。
4. 进入 `ended` 后，Undo 与作弊交换一律不可用。
5. Time Attack 是唯一「时间到强制结算」的模式，其余模式的终局都可由玩家延迟。

## 4. 长局存储与撤销

产品承诺：**不设撤销步数上限，不静默丢弃历史**（ADR-0003）。

初版实现：**每步保留完整前态快照**，并实测规模后决定持久化表示。

### 必须实测的指标

在 **5×5 模式**下，对 **1,000 次**与 **10,000 次**有效操作分别测量：

| 指标 | 1,000 次 | 10,000 次 |
| --- | --- | --- |
| 内存占用（撤销栈） | 待测 | 待测 |
| 序列化后写入量 | 待测 | 待测 |
| 刷新后恢复耗时 | 待测 | 待测 |

持久化优先考虑 **IndexedDB**。

**降级路径**：若实测成本过高，改为**可重放操作日志 + 检查点**，但必须保持「撤到开局」的
行为不变。

**写入失败时**：保留当前页面内的撤销能力，并**明确提示刷新后可能无法续玩**；
不得把未保存的历史称为可恢复。

**边界**：不得把测试规模（1,000 / 10,000）说成浏览器容量保证——这是实测参考点，不是上限承诺。
