# Classic · 设计卡

> 风格 id：`classic`。本卡是这套风格与 T23 视觉复核逐项对照的依据，先于 CSS 写成。
> 参考原型：Gabriele Cirulli 的 [2048](https://github.com/gabrielecirulli/2048) ——
> 暖米色纸面、棕色圆角方块、全扁平、无渐变；**静态版面**无投影。

## 1. 参考与氛围

- **可辨识的参考**：原版 2048 的第一屏——奶油色底、棕色棋盘、暖色方块阶梯、右上角分数盒。
  看到这屏的人应当能一眼认出「这是 2048」，而不是「某个 2048 仿品」。
- **气质**：纸感、安静、玩具级友好。没有科技感、没有拟物、没有玻璃。
- **唯一允许的装饰**：方块合并时的一次轻微放大回弹（T21 落地），以及目标达成时
  胜利面板标题的一次轻微进入反馈。除此之外不做装饰。

## 2. 色彩角色

全部色值由 `tokens.css` 提供，`board.css` 只负责把色值贴到固定 DOM 上。

| 角色 | 变量 | 色值 |
| --- | --- | --- |
| 纸面（页面底） | `--page` | `#faf8ef` |
| 棋盘框 | `--board` | `#bbada0` |
| 空格 | `--cell-bg` | `#cdc1b4` |
| 障碍（Walls 模式的四格固定障碍） | `--wall-bg` | `#3f4a52` |
| 正文 / 小字 | `--ink` | `#5f564e` |
| 亮底方块上的字 | `--ink` | `#5f564e` |
| 次要正文（纸面上的小标签） | `--ink-variant` | `#766e66` |
| 深底方块上的字 / 控件上的字 | `--ink-bright` | `#f9f6f2` |
| 次要正文（面板上的小标签） | `--ink-bright-variant` | `#e4e0da` |
| 控件底 | `--control-bg` | `#6f6055` |
| 控件悬停 | `--control-bg-hover` | `#5f564e` |
| 焦点 | `--focus` | `#4a443f` |
| 方块阶梯 | `--tile-1` … `--tile-11` + `--tile-beyond` | 见表下 |

方块阶梯按**色档**命名（T13 起），不按数值：档位是「在本模式目标前的相对进度」，由
`components/ValueLadder.ts` 从模式已声明的 spawnValues + target + mergeFamily 推出来。
经典模式 11 级阶梯与 11 个色档一一对应，所以下表左列的数值也就是档位；到了别的模式
（斐波那契 17 级、大棋盘 12 级）同一个档装的是不同数值——第 11 档在斐波那契是 2584、
在大棋盘是 4096。所以这些名字描述的是进度，不是数字。

方块阶梯（第 1–2 档用亮底深字，第 3 档起用深底亮字）：

| 数值 | 底 | 数值 | 底 |
| --- | --- | --- | --- |
| 2 | `#eee4da` | 128 | `#916a0e` |
| 4 | `#ede0c8` | 256 | `#8a680d` |
| 8 | `#c2622c` | 512 | `#85640b` |
| 16 | `#b5561f` | 1024 | `#7c5d0a` |
| 32 | `#a54a1c` | 2048 | `#6c5109` |
| 64 | `#953f18` | 超出本模式目标值 | `#4a443f` |

阶梯的取舍不是「挑好看」，是「每一档都过线」：8 号是唯一低于 4.5:1 的一档
（3.84:1），但它永远是**一位数**，字号最大，按大字 3:1 走；其余每一档都 ≥ 4.56:1，
连窄屏小格子上缩小的字号也算普通文字也过线。这样「字号随位数变化」就不会反过来
拉扯对比度口径。

**障碍（T07 新增，`#3f4a52`）**：冷灰，刻意落在上面这条暖色阶梯之外。理由是障碍必须
同时与「可玩空格」和「数值方块」分得开，而阶梯里最暗的一档 `--tile-beyond`
（`#4a443f`）**本身就是一档方块**——复用它会让 4096 及以上的方块与障碍同色。所以
障碍另起一个色值，并且不带数字：方块永远带数字，障碍永远不带，「朝它按方向键」这个
误操作就没有落脚点。这一条是判据，不是装饰。

**新风格的 `tokens.css` 必须声明 `--wall-bg`**：`board.css` 的 `[data-cell='wall']`
直接读这个变量，而棋盘固定结构不属于任何一套风格（ADR-0002），所以它是每一套风格
都要交的色值，不是 classic 的私事。哪一套漏了它，那条声明在计算值时无效，
`background` 退回 `transparent`——墙会变回**四个看不见的洞**，也就是 T07 修掉的
那个 bug，而且浏览器一个字都不报。加新风格时先对照本表的角色清单核一遍。

**对原版配色的刻意偏离（要写进复核结论里）**：原版的 `#f2b179` 亮橙配白字只有
**1.7:1**，`#8f7a66` 控件配白字只有 **3.8:1**，都过不了 SPEC §3.2 的阈值。
做法是整条阶梯加深一档、控件改用更深的棕，而不是把字改黑——暖色家族与「深底亮字」
的层级关系都还在，只是抬到了 3:1 / 4.5:1 之上。实测比值见 `contrast.json`。

## 3. 字体角色

- **展示**：标题「2048」与分数数字 → `Inter`，700。
- **正文**：界面标签、按钮、说明 → `Inter`，400 / 600。
- **方块数值**：`Inter` 700 + `font-variant-numeric: tabular-nums`（数字等宽，
  合并时不抖）。
- **回退**：同字形类别，`var(--fallback-grotesk)`（ADR-0005）。缺字时整套风格
  在无衬线一类内降级，不会变成衬线或等宽。
- 数字永远是西文：`unicode-range` 只有 latin 子集，中文不会触发本地字体请求。

## 4. 布局与密度

- 单列居中：标题 → 分数 / 目标 / 最高方块 → 棋盘 → 操作提示。
- 紧凑密度：信息条一屏放下，棋盘始终完整可见，不为装饰预留第二条滚动屏。
- 棋盘是页面唯一的视觉主体，其他元素都退到「纸面上的标注」这一层。
- 棋盘尺寸由模式数据决定，但**格子边长、间距、内边距只有一份数值**，在
  `components/BoardLayout.ts`：`board.css` 只消费 CSS 变量，不抄第二份。

## 5. 棋盘与外壳的区别处理

- **棋盘层**（`board.css`，不用任何 Tailwind utility）：固定 DOM 结构 + `boardOverlay`
  / `tileOverlay` 两个装饰插槽。带内边距的棕色底板、圆角空格、圆角方块。
- **外壳**（Tailwind utility + 本风格 `styles.css` 的语义类）：管页面底色、文字色、
  间距与响应式。外壳可以换实现，棋盘结构一行都不能改（ADR-0002）。
- 两者共用同一套 token，所以「换风格」只换 `themes/<id>/` 一个文件夹。

## 6. 独有装饰与动效

- **位移**：150ms + `ease-out`；三套风格共用这条空间曲线，快速输入
  时仍从当前画面重定向。
- **合并**：产物轻微放大到 1.08 再回落，两段 CSS scale 过渡合计 80ms；React 提交回落阶段时增加的帧间隔会延长浏览器观察到的总时长。来源块保持不透明并落在产物下面。
- **生成**：新方块从 0.6 透明度和 0.94 倍尺寸淡入，120ms。
- **结果层（T26 · ADR-0008）：半透明遮罩 + 不透明卡片**，不再是盖住棋盘的一层纸面。三种
  非对局阶段（达标 / 死局 / 已结算）共用同一结构：`.overlay` 是棋盘那只盒子里的一层定位壳，
  `.overlay__scrim` 盖住棋盘，`.overlay__card` 坐在遮罩上，带着标题、那一句话、四项读数与按钮。
  结构与三档映射在 `styles/index.css`，卡片的长相在本风格的 `styles.css`，遮罩的三个数值在
  `tokens.css`——**这不是第四个插槽**（ADR-0002 的插槽判据见 ADR-0008 的 Consequences）。
  - **这一套的遮罩压暗棋盘，而且压得看得见**：本套的全部词汇就是「墨写在纸上」，所以遮罩用
    本套自己的墨色（`--result-scrim-*`，三档 rgba 字面量）。方块透过它明显暗下去——**是的，
    这一套的遮罩让棋盘退后了**，这正是它要做的。改动前写在 `styles.css` 上的旧理由（「半透明会
    把结束的方块透出来，看着像还能动」）说的其实是「读成活的」，而遮罩把证据标成「停住的」，
    不是把证据删掉：明暗差就是这句话。褪一层纸色不回答它，只是把它挪个地方（ADR-0008 原文）。
  - **三档强度**按「还剩多少决定可做」排：死局最亮（0.38，玩家得看清棋盘才选得出撤销、交换
    还是认命）、达标居中（0.5）、结算最暗（0.66，什么都不用决定了）。三套不共用一组 alpha：
    各家墨色明度不同，同一个 alpha 在三张纸面上不是同一种压暗（Material 0.30 / 0.42 / 0.58、
    Claude 0.34 / 0.46 / 0.62）。
  - **卡片不透明**，底色仍是纸面 `--page`，所以它上面每一对文字与按钮的对比度与改动前逐字节
    相同。这正是分成两个元素的原因——§7 禁「用 opacity 调文字明度」，而半透明前景是另一个
    颜色值、闸门读不到合成结果。卡片内边距 1rem（原先是 `.overlay` 上那一个，值一个都没改）。
  - **四项读数**是一行小字脚注（分数 / 最高分 / 步数），外加一行「本局刷新了最高分」的标记。
    数字等宽、标签用次要墨色、不用大写、不用序号、不用间隔点、不加「本局数据」之类的小标题——
    读数是那句标题的注脚，不是又一处主角。最高分按结算那一刻的风格归属，新纪录判定是纯函数
    （`stores/records.ts` 的 `resultReadout`）。结构只有一份（`components/ResultLayer.tsx`），
    两个面板把自己的标题、那一句话与按钮递进去，文案逐字节未改。
- `prefers-reduced-motion: reduce` 下位移、缩放停止；生成与合并保留静止描边，胜利标题只淡入。
  结果层这一版**没有进出动效**（它硬切进场），那是下一票（T27）的事；届时本节随它补，
  而遮罩与卡片的长相一个字段都不该变——降级的只是「怎么动」。
- **本风格不用**：渐变、投影（成就祝贺那一层例外，见 §7）、玻璃、扫描线、斜角、网格纹理、任何堆叠层。

## 7. 禁用的通用样式

- 禁 Tailwind 调色板色值出现在棋盘与方块层（连 `bg-slate-100` 都不行）。
- 禁 `box-shadow` 充当投影或伪立体（这一套全扁平，Elevation 是 Material 的语言）。
  **第一个例外是§9 那一对焦点双环**：`box-shadow: 0 0 0 2px var(--page), 0 0 0 4px var(--focus)`
  画在控件与棋盘上，实现见 `styles.css:81` 与 `:180`。它不是投影伪造——投影会让人以
  为那一层被抬起，双环说的是「焦点在这里」。也不用 `outline` 实现：outline 只能画一
  圈，「页面色垫圈 + 深色描边」需要两个同心圆，而垫上去的第二条 border 会改盒子尺寸
  （Claude 设计卡 §5 记着同一条代价）。T13 曾把这条禁项写成「焦点环用 outline」，与
  §9、`contrast.json` 的 ring 探针相互矛盾；**T23 更正为上面这句**，实现一个字节没动。
- **第二个例外：成就祝贺那一层投影**（2026-09-28 应所有者要求）。它是**瞬时浮层**，不属于页面的静态层级；影用本套自己的墨色 `#4a443f` 调低、扩散小，读起来是「一张压在纸上的卡片」，不是 elevation。见 §10。除此之外仍然禁投影。
- 禁渐变背景、禁 `filter`、禁 emoji 当装饰（棋盘、方块与外壳的静态部分）。
- 禁把方块做成 `<button>`：方块是状态不是控件，交互归棋盘根元素。
- **T15 起禁用 `opacity` 调文字明度**：半透明前景是另一个颜色值，`getComputedStyle().color`
  读不到合成结果，对比度闸门只能从 `style.opacity` 回头补算（那是绕开，不是修好）。
  次要文字另声明色值——本套是 `--ink-variant`（纸面）与 `--ink-bright-variant`（面板）。
  **结果层的遮罩不是这条禁令的旁路**（§6）：它调的是**棋盘底色**（`--result-scrim-*`，三档
  rgba 字面量），卡片上的文字一个字节都不半透明，所以这一层没有把任何一对文字推出闸门的量程。
- 禁在 `src/game/` 里出现任何本风格的引用（ADR-0001）。

## 8. 手机窄屏策略

- 视口 ≤ 520px 时格子边长收缩，间距与圆角同比缩小，棋盘仍完整落在屏内。
- 信息条从横排改为竖排堆叠，分数不被裁切。
- 触屏操作归 T10；本风格只保证窄屏下没有横向溢出、文字不换行断裂。
- 操作提示在窄屏缩短为「方向键 / 滑动 移动方块」。

## 9. 对比度与无障碍

- 正文与小字按 4.5:1 走，方块数值也按 4.5:1 走——**唯一例外是 8 号**（按大字 3:1，
  理由见下）；非文字指示器（焦点环、选中环、障碍）按 3:1 走。所有实际组合与实测比值
  列在 `contrast.json`，T14 的 `npm run check:contrast` 照它校验。
- **T14 起每一对都写明口径（`basis`）、测量场景（`scene`）与探针（`probe`）**：口径
  是 regular / large / non-text 三选一，且与 `minimum` 必须自洽（4.5 / 3 / 3）——
  「哪一对靠大字豁免」因此是表上的一个字段，而不是谁脑子里的一句话。场景是
  start（开局界面）/ run（局中）/ walls（墙模式）；探针是那一对在页面上真正被量到的
  元素，浏览器那一层（tests/e2e/contrast-computed.spec.ts）按它读计算样式。声明对了
  不等于渲染对了——选择器失效、漏了 data-style 这类事，只有那一层抓得到。
- **T14 补了三笔此前没人量的账**：
  1. **选中环 vs 空格底 5.43:1**（`#4a443f` on `#cdc1b4`，basis: non-text）。T12 复核
     时发现带 spread 的 box-shadow 画在 border box 外侧、落在 `--cell-bg` 上，而表上
     那个 `--focus` 条目是与**页面色**的 9.01:1，这一对不在表内。现已按非文字指示器
     入表，`probe` 是 `[data-selected='true']` 的那枚方块加一个空格。
  2. **面板小标签 4.59:1**（`.panel__label` 的次要色 `--ink-bright-variant` `#e4e0da` 压在
     `--control-bg` 上）。**T15 起它不再是合成结果**：同一个 `.panel__label` 既在纸面上
     又在深棕面板里，当年两处都靠 `opacity: .85` 把本色压向各自的底色——半透明前景不是
     「打了折的同一个颜色」，是另一个颜色值，而 `getComputedStyle().color` 拿到的是
     **合成前**的那个（T14 的闸门只能从 `style.opacity` 回头补算，那是绕开而不是修好）。
     现在两处各自显式声明次要色（`--ink-variant` / `--ink-bright-variant`），两个值就是当年
     合成出来的那两个颜色，所以 Classic 的渲染逐字节不变、复测仍是 4.59——变化的只是
     「这一对现在能不能被计算样式直接读出来」。**这是全表贴线最紧的一对，复核先看它。**
     方向要说清楚：这一对里小标签是**更亮**的那一边，所以想给它「加深一档」会让它掉下去；
     要余量只能调亮（或调深面板底），那是配色裁决，不是实现细节。
  3. **开局界面的分组小标签 4.71:1**（同一个 `.panel__label`，在纸面上压的是 `--ink-variant`
     `#766e66` 而不是 `--ink-bright-variant`）。一个类在两种底色上就是两对不同的值，
     两者都过线（Material 的分组小标签同理，见其设计卡 §9）。
- 数值字号按位数分档（0.45 → 0.2 倍格边长），跟着格子等比缩。唯一依赖大字口径的是
  8 号（3.84:1），而它**永远是一位数**、字号最大：桌面格边长 100px ⇒ 字号 45px；
  窄屏 `fitCellSize(4, 393)` 得 71px 格边长 ⇒ 字号 0.45×71 ≈ 32px（试玩日志里窄屏
  棋盘 344px、71px 格子，与此一致）。**32px 仍是 `font-weight: 700`，高于 WCAG 大字
  口径 18.66px（14pt 粗体）的下限，所以对比度结论不变**——这只是把原先「≥38px」
  这个数字改对，不是把门槛放松。
  其余每一档都 ≥ 4.56:1，所以窄屏上长数值缩到 24px 以下也算普通文字，仍然过线。
  这样「字号随位数变化」就不会反过来拉扯对比度口径。
- 焦点用「页面色垫圈 + 深色描边」的双环：`box-shadow: 0 0 0 2px var(--page),
  0 0 0 4px var(--focus)`，深色环永远只与页面色相邻，在深浅控件上都 ≥ 6:1。
- 空格与棋盘框的 1.24:1 是**装饰关系**，不承载信息：真正要区分的是「方块 vs 空格」
  （1.41:1 起，原版同值），它按纸面的明度层级成立，不按指示器阈值成立。
  这一点明确记在这里，免得后续复核把它当成漏项。
- **T07 把这条 exclusion 收窄到「空格 vs 棋盘框」，没有把它废掉。** 经典模式里每个
  可玩格长得一模一样，「哪一格能否放方块」这件事不存在，所以 1.24:1 不承载信息；
  到了 Walls 模式，墙 vs 可玩空格回答的正是「哪些格能放方块」，于是它变成一条
  **承载信息**的指示器关系，必须按非文字指示器的 3:1 走。实测 `#3f4a52` vs
  `#cdc1b4` = **5.14:1**，已列入 `contrast.json`。「空格 vs 棋盘框」那一对仍然不在
  表内——它依旧只是纸面的明度层级。
- **墙 vs 数值方块没有第二道比值要满足**，这是同一处收窄的另一半，写下来免得 T23
  再翻案：方块永远带数字、障碍永远不带，这已经是两者最强的判据；再加上障碍色值落在
  方块阶梯的暖色之外，没有哪一档方块会与障碍同色。更重要的是，**不存在**一个能对
  2048 档清出 3:1 的墙色：`#6c5109` 亮度 0.090927，墙要比它暗且拉到 3:1，需要墙的
  亮度 ≤ (0.090927 + 0.05) / 3 − 0.05 = **−0.0030**——是**负数**，而亮度不可能低于 0，
  所以任何真实色值都无解。连纯黑也够不到：纯黑 vs `#6c5109` 只有 **2.82:1**
  （(0.090927 + 0.05) / 0.05）。阶梯两端同样撑不开窗口：最亮 `#eee4da` 亮度 0.787，
  最暗 `#4a443f` 亮度 0.060，离最亮 3:1 要求 L_wall ≤ 0.229086，离最暗 3:1 要求
  L_wall ≥ 0.278469，上界小于下界，窗口为空。
  （顺带钉住一个容易写错的口径：`#eee4da` 与 `#4a443f` 的**亮度之比**是 13.23，
  而 WCAG 的**对比比值**是 7.65:1 —— (0.787259 + 0.05) / (0.059490 + 0.05) = 7.6469。
  注意算式里只能用**全精度**亮度：若按上句那样截成 0.787 与 0.060 再算，会得到 7.61，
  与这里宣称的 7.65 对不上——那正是会引来翻案的那种数。两个口径不一样，别拿前者当后者。）
  所以这不是「还没挑到合适的色值」，是算术上无解；要凑齐就得把阈值降到 3:1 以下，
  那是所有者级别的配色裁决，不是实现里能顺手改的值。
- **成就祝贺（toast）不新增色对**：它只用 §10 列的、本表已经量过的那两对
  （`--ink-bright` on `--control-bg` 5.60、`--ink-bright-variant` on `--control-bg` 4.59）。
  于是闸门一行都不用改，这一条装饰也不欠任何对比度的账。
- **结果层（T26）同样不新增色对**：四项读数的标签是 `--ink-variant` 压在卡片的那一层纸面上，
  而卡片底色就是 `--page`——「`#766e66` on `#faf8ef` = 4.71:1」这一对本表里已经有（纸面上的
  分组小标签，scene: start）。数字与那句「本局刷新了最高分」用 `--ink`，同样是既有的一对。
  遮罩这三个 rgba 值是**棋盘底色**，不是文字前景，因此不进入本表——闸门量的从来是文字。
- 本卡按「承载信息的对比 3:1，不承载信息的不凑数」收口。

## 10. 成就祝贺（toast）

解锁一个成就时浮出的一条短提示（ADR-0007；词汇见 `CONTEXT.md` 的 Toast 词条）。它是
**每套风格自己实现的呈现插槽**（ADR-0002），所以这一节是本套的长相与消失表现，
而「什么时候该有一条」全在 store。

**位置与堆叠**

- `position: fixed`，贴视口**上方正中**：`top: 1rem`、`left/right: 1rem`，`align-items: center` 让它落在正中。
  **不进文档流**——流内的一条提示会把棋盘整体推下去，正在打的一局当场错位。
- 宽 `min(22rem, calc(100vw - 1.5rem))`；最多三条，**最新的一条在最上**，
  自第二条起向下排（gap `0.5rem`）。第四条到达时丢最旧（单局成就规格的架构决策 6），
  所以「刚拿到的那条」永远在最上、位置最稳。
- **为什么在上方正中**：棋盘在页面正中、方向按钮在它正下方（触摸设备上是一整行），
  上方正中是这两处之外、且手机与桌面都留得出空的地方；**居中**让最新那一条落在视线落点上。
  ≈ `11rem`，仍落在棋盘上沿之上。
- 容器 `pointer-events: none`、每张卡片 `pointer-events: auto`：卡片**之外**的点击
  穿透到下面的控件，所以它不拦操作。

**结构**

`div.toast-stack > div.toast[role=status][tabindex=0]`，里面**两行**：上行 `.toast__head`
（`.toast__emoji` + `.toast__names`：图标与名字按同一批次并排，如 `🧩🏆`），下行 `.toast__note`
容器与每一条都用 `div` 而不是 `ul`/`li`：这些是**状态消息**，不是「一列东西」；`role="status"` 会把 `listitem` 覆盖掉，剩下的那个 `ul` 在无障碍树里就是一份空列表。一次跃迁里满足几个名字就写几个，用「、」连起来——一条提示，不是每个成就一条。

**图标与声音**（2026-09-28 应所有者要求补的）。上行那个图标取自注册表（`AchievementDefinition.emoji`，三套共用一份——各抄三份必然漂开），它对读屏软件隐藏：名字已经把「拿到了哪一个」说全，多念一遍「拼图块」只是噪音。下行是这一套风格的声音：`解锁成就 · <祝词>`，本套的祝词是「干得漂亮，接着来」。祝词**只说实话**——它是道贺，不是「战绩已写入」这类会被证伪的声明。内边距 `0.625rem 1rem`，两行之间 `0.25rem`。

**色彩与字体**

| 用途 | 令牌 | 色值 | 对比度 |
| --- | --- | --- | --- |
| 卡片底 | `--control-bg` | `#6f6055` | — |
| 成就名 | `--ink-bright` | `#f9f6f2` | 5.60:1（与 `.panel__value` 同一对） |
| 下行（`.toast__note`：`解锁成就 · 祝词`） | `--ink-bright-variant` | `#e4e0da` | 4.59:1（与面板小标签同一对） |

圆角 `--cell-radius`（6px），字体 `--font-body`，成就名 600、下行 400。**带一层自己的投影**（`0 2px 8px rgba(74, 68, 63, 0.3)`，§7 的第二个例外）：
Classic 的层级是深底压在纸面上说出来的，不用 elevation 伪造（§7 的禁项）。

**动效**（沿用全局那条空间曲线 `ease-out`，§6）

- **进**：`opacity 0→1` + `translateY(-6px)→0`，**180ms**。
- **停**：进场结束之后可见 **5000ms**；指针悬停在这一条上或焦点落在它里面时**暂停计时**，
  移开 / 失焦接着走剩下的时间（不重新计满）。
- **出**：`opacity 1→0` + `translateY(0)→-6px`，**200ms**，动画结束再从栈里移除。
- **`prefers-reduced-motion: reduce`**：进 / 出时长归 0（直接出现、直接消失），
  **长相一个字段都不变**——降级的是「怎么动」，不是「长什么样」。

**无障碍**

- `role="status"`（隐式 polite + atomic）：每条只播报一次，且整条在场期间一直留在
  无障碍树里，读屏用户可以回头再读（不是「念完就没了」）。
- `tabindex="0"` 让它进 Tab 顺序——「焦点在内时暂停」正是靠它成立的。但**从不自动抢焦点**：
  解锁不改变 `document.activeElement`，方向键照旧归棋盘。
- 焦点环沿用本套的双环（§9 那一对），深色环仍然只与页面色相邻。

**约束核对**：不遮棋盘（贴顶、最多三条，单条约 `3.5rem`）· 不压方向按钮（在页尾，离顶部最远）·
不拦操作（容器穿透）· 三条同屏仍可读（每条两行：上行图标 + 名字、下行这一套的祝词）。

## 11. 一念神魔（彩蛋 · 外壳不是插槽）

打出口令之后，机器答话递过来的四样东西：**两颗圆钮**（A 与 B）、**一念**那颗药丸按钮、
**礼炮**（两上角那一发粒子）与**悬顶**（走火入魔之后钉在视口顶端的那条）。结构、摆位与
两段 30 秒全住在共享外壳 `styles/index.css`（父规格的架构决策 11：彩蛋不是第四个插槽），
本套只出**底面、描边与投影**——所以这一节是本套对这四样东西的说法。

| 用处 | 令牌 | 色值 | 与谁同一族 |
| --- | --- | --- | --- |
| 圆钮底 / 一念底 | `--shenmo-button-bg` / `--wish-bg` | `#6f6055` | 与 `.control` 同一个棕 |
| 圆钮字 / 一念字 | `--shenmo-button-ink` / `--wish-ink` | `#f9f6f2` | 与 `.control` 同一对 |
| 描边 | `--shenmo-button-border` / `--wish-border` | `#faf8ef` | 页面色（不是墨） |
| 那道环 | `--shenmo-ring` | `#4a443f` | 与 `--tile-beyond` 同一个墨 |
| 悬顶 | `--shenmo-strip-surface` / `--shenmo-strip-ink` | `#6f6055` / `#f9f6f2` | 与圆钮同一对 |

**B 碎掉的那一刻**：整颗钮从中间裂成两半、各带一个 B，朝上下反方向飞走并一起淡掉
（150ms，`ease-out`）。**本套的说法是没有说法**——两片碎渣就是这块深棕自己裂开，
不发光、不冒烟、不抖动；字在裂开之前已经隐去，两片各带一个 B 是伪元素，所以读屏软件
不会把它念第二遍。裂完之后只剩 A，而 A 上那道环用**本套最深的墨**（`--shenmo-ring`）
向里收——时间是墨在变薄，不是一圈额外的颜色。

**一念那颗按钮**与 `.control` 同族颜色、不同形状：药丸形 + display 字体 + `letter-spacing`
（§2）。它读起来是「机器递过来的东西」，不是「这一局的又一个操作」，所以形状是它唯一的
分岔。**不带投影**（§7 的全扁平不破例），描边同样用 `outline` 而不是 `border`——border
会让 3rem 的圆钮大一像素，而它在宽视口下是贴着 `translate` 探出去的。

**悬顶**是一条压满宽度的深棕色带（与圆钮、一念同一个棕）：满宽、齐边、不消失。它**刻意
不像 toast**——那是圆角、居中、限宽 24rem 的一张卡；这一条是「这一局现在归这块颜色管」。
两条共用视口顶端而不重叠，靠的是外壳那个 `--toast-top`。

**堕落染墨**（点过 B 之后那 30 秒）不动这一节的任何颜色：暗下去的是十二档方块令牌
（`tokens.css` 里同名同作用域的那一组），外壳与彩蛋自己的四个面一个字节都不改。

**约束核对**：不遮棋盘（容器 `pointer-events: none`，只有两颗钮自己接）· 宽视口嵌在包住
棋盘的那只壳里向两侧探出，窄视口落到棋盘下一行（父规格架构决策 12，两个视口都不横向
溢出）· 键盘可达（Tab 到两颗钮、回车 / 空格激活、Esc 收起）· reduced-motion 下进场退化成
一次淡入、两片碎渣一个都不渲染，而两段 30 秒照旧到期（父规格架构决策 4）。
