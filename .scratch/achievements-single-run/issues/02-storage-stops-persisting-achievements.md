# 02: 存储迁移：成就不再落盘

**What to build:** 结算时写下的统计记录里不再有任何成就数据；同时解码器对**陌生**的成就 id 与未知
字段变得宽容——丢掉它、保住其余统计数字。玩家侧的可观测结果是：一次结算之后桶里读不到成就；
而一份旧版形状（里面还写着已退休成就 id）的记录被加载时，四项统计照常显示，不再因为一个不认识
的 id 整条作废。不升数据库版本，不写迁移脚本：记录在下次结算时整条重写，旧字节自然消失。

**Blocked by:** 01（成就的形状变了，写入方跟着变）

**Status:** ready-for-agent

- [x] 统计记录里不再有成就字段；结算一次之后，桶里读不到任何成就数据
- [x] 解码器遇到未知成就 id / 未知字段时**丢掉它并保留其余部分**，而不是整条拒绝
- [x] 用旧版形状（含已退休成就 id）预置一条统计记录，加载后四项统计照常显示
- [x] 旧的「整条拒绝」行为**没有被放宽**：形状本身是垃圾的记录仍然被拒
- [x] 没有 `DB_VERSION` 变更，没有迁移脚本
- [x] `npm run typecheck`、`npm test`、`npm run build` 全绿

## Evidence（2026-09-28 实现会话）

- `StatsRecord` 去掉 `achievements` 字段；`emptyStats` / `applyRunToStats` 不再碰它
  （`applyRunToStats` 现在直接返回 `StatsRecord`，`SettlementWrite` 也去掉了 `unlocked`）。
- `decodeStats` 逐项取出自己认识的五个字段并交出一份**只有那几个键**的记录：未知字段
  （包括上一版的 `achievements` 块、里面已退休的成就 id）一律丢掉，其余照读。
- **没有 `DB_VERSION` 变更**（仍是 `sessionStore.ts` 的 `DB_VERSION = 2`），**没有迁移脚本**；
  旧字节靠下一次结算整条重写自然消失。
- 旧的「整条拒绝」没有被放宽：`totalRuns` 是负数、`version` 对不上、`lastRunStartedAt` 是 0
  这类**形状本身是垃圾**的记录照旧 `rejected`（单测 `records.test.ts` 的两组用例；
  实测路径由 `records-settle.test.ts` 的「统计桶形状坏了」钉住）。
- 用例：单测 `records.test.ts` 的「解码器对旧版形状宽容」三条 + `records-settle.test.ts` 的
  「带成就块的旧版统计：照旧读得出来，也照旧写得进去」+ e2e `records.spec.ts` 的
  「上一版写下的统计（带已退休的成就 id）照旧显示，不整条作废」。
- **与票面措辞的一处偏离**：票面说「加载后**四项**统计照常显示」。落地之后面板上显示的是
  **三个**数字——第四格（「成就解锁」计数）按 01 撤下了，它是那块面板唯一一处声称解锁状态的
  地方。记录本身照旧被完整读出来（三个计数 + 幂等键一个都没少），这正是本条要保的东西。
