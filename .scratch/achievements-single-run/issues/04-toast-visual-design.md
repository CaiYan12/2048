# 04: toast 的坐标与视觉（`/design-flow`）

**What to build:** 三套风格各自的祝贺提示长什么样、出现在哪里、怎么进怎么出。规格只给了约束，
坐标与视觉刻意留给设计流程——因为「Classic 的纸感、Material 的层次、Claude 的暖调」这件事推不出来，
只能设计出来。

**Blocked by:** None（可与 01–03 并行）

**Status:** ready-for-agent

- [x] 走 `/design-flow`，三套风格各出一份 toast 方案
- [x] 满足规格的约束：**不遮棋盘**、不压四个方向钮、不拦操作，三条同屏时仍然可读
- [x] 进 / 停 / 出三个阶段的时长与曲线写清楚，并与共享契约一致（约 5 秒自动消失、
      悬停或聚焦时暂停）
- [x] `prefers-reduced-motion` 下的降级方案写清楚（降级不等于换一种长相）
- [x] 结论落进各风格的设计卡（`DESIGN.md` 的相应小节），供实现票直接照做
